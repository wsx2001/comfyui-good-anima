# 产品需求文档（PRD）

> 作者视角：资深后端 / 数据平台 PM
> 版本：v1.1 · 修订
> 日期：2026-08-23
> 项目：[PROJECT.md](./PROJECT.md) → 配套 v2mini 的本地 AI 对话生图工具

---

## 1. 背景

`comfyui-good-anima` v2mini 已经是一套成熟的 AI 生图技能包：情境因果 → 三层 prompt → Danbooru 标签校验 → ComfyUI 执行，整套链路在 AI 编程助手（Snow / Codex / Claude Code）中跑得通。但它有两个使用门槛：

1. **必须懂 AI Agent** — 用户要在 AI 编程助手里反复提示，让 agent 决定何时触发哪个 skill。
2. **没有可视化反馈** — agent 在终端里吐 JSON / 命令行结果，用户看不到"它在生什么图、想什么"。

这导致大量**会用 ComfyUI 但不愿意在 AI agent 里反复调试 prompt 的创作者**被挡在门外。

## 2. 目标与定位

**做一款本地 Web 应用**：通过浏览器聊天框，让普通创作者像发微信一样使用 v2mini 生图技能，无需接触 AI Agent、无需手写命令。

| 项目          | 描述                                                                 |
| ------------- | -------------------------------------------------------------------- |
| **产品形态**  | 本地独立 Web 服务（`127.0.0.1:8787`）+ 浏览器前端                     |
| **目标用户**  | 单机创作者，懂 ComfyUI 但不愿在 AI agent 里手写提示词的二次元向作者  |
| **核心价值**  | 把 v2mini 从「Agent 的工具」变成「人类创作者的工具」                  |
| **成功标志**  | 用户每天打开浏览器就能聊出图，不必再开 IDE / Terminal                |

## 3. 范围

### 3.1 v1 范围内（In Scope）

| 模块                 | 说明                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------- |
| 对话交互             | 单会话多轮对话、流式响应、Markdown 渲染、消息重发                                     |
| 生图执行             | 调用 v2mini 链路生成单张图（含视觉简报、三层 prompt、Danbooru 校验、执行）            |
| **双模式工作流**     | **默认 v2mini 5 个 workflow**（保持 Anima 硬约束）+ **高级模式：导入任意 ComfyUI workflow JSON 并指定 prompt 注入节点** |
| **场景列表串行生图** | **用户在对话中说"依次生成 N 个场景"，LLM 拆解为任务队列，工具串行逐张生图**            |
| 结果展示             | 缩略图网格、大图预览、原始 prompt / args 详情、下载                                    |
| **LLM 参数调节**     | **上下文保留轮数、max_tokens、temperature、思维深度档位**                              |
| 会话管理             | 创建、列表、打开、删除、重命名会话                                                    |
| 任务管理             | 查看运行中任务、取消任务、查看失败原因                                                |
| 队列管理             | 暂停 / 恢复 / 取消 / 追加任务、整队完成提示、ZIP 导出                                  |
| 配置                 | LLM API / ComfyUI 服务 / 技能根目录 / LLM 参数                                        |
| Launcher             | ComfyUI 自定义节点，单按钮跳浏览器                                                    |

### 3.2 v1 不做（Out of Scope）

- 多用户 / 鉴权 / 远程访问
- 画师融合（`artist-mixer` workflow 仅作为可选项暴露，不专门做 UX）
- 图生图（i2i workflow）
- 工作流画布编辑器（节点拖拽式）
- 模型 / LoRA 管理
- ComfyUI 队列调度优化
- 多 LLM 路由 / 智能切换

## 4. 目标用户与典型场景

### 4.1 用户画像

**Primary**：单机二次元创作者

- 已有 ComfyUI、本地模型、显卡
- 写过 prompt，懂基础 Danbooru 标签
- **不愿** 在 AI 编程助手里反复提示 agent，希望像聊天一样出图
- 日均生图 5–50 张，常需要迭代微调
- 偶尔会想要"一次聊出多个变体"或"批量跑一组场景"

**Secondary**：v2mini 现有用户

- 已经在用 Snow / Codex 触发 v2mini
- 想有一个**视觉化的对话界面**，替代 terminal JSON 流
- 偶尔需要在不同设备上查看历史
- 偶尔需要切换工作流（如想试 artist-mixer 而不只是默认 aesthetic-lora）

### 4.2 典型场景

| 场景                  | 描述                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------- |
| **A. 标准生图**       | "画一张立华奏在雨中的天台，rella 画风"                                                              |
| **B. 迭代微调**       | "刚才那张再忧郁一点"、"把画师换成 wlopp"、"背景换成教室"                                            |
| **C. 参数控制**       | "这批出 4 张"、"改成 16:9 横构图"、"steps 调到 40"                                                  |
| **D. 批量与变体**     | "用 rella 出 10 张随机姿势"（MVP 仅支持基于同一 prompt 的 batch_size）                             |
| **E. 取消与重试**     | 用户在生成过程中修改描述并重新提交，需取消之前的任务                                                |
| **F. 历史回看**       | "昨天那张图再发我一次"、"那条会话继续聊"                                                            |
| **G. 配置变更**       | 切换 LLM 提供方、修改 ComfyUI 地址、修改技能根目录、**调整上下文轮数 / 思维深度**                   |
| **H. 场景列表串行**   | **"依次生成：1. 立华奏雨中天台 2. 雾雨魔理沙魔法森林 3. 八云紫夜晚书房"，工具自动拆解并串行生成** |
| **I. 工作流切换**     | **"用 artist-mixer workflow 出下一张" / "切到 base workflow 对比一下"**                           |
| **J. 自定义工作流**   | **（高级）导入自定义 ComfyUI workflow JSON，UI 指定 CLIPTextEncode 节点作为 prompt 注入点**        |

## 5. 用户故事与验收标准

> 格式：作为 [角色]，我希望 [能力]，以便 [价值]。
> 每条故事都对应可测试的验收标准（AC）。

### US-1 标准生图（场景 A）

> **作为** 创作者，**我希望** 用一句话描述想要生成的画面，**以便** 工具自动完成视觉简报、标签校验与 ComfyUI 提交。

**AC：**

- [ ] **AC-1.1** 在对话框输入自然语言描述（≥10 字），点击发送后 ≤3s 内开始流式输出 LLM 思考
- [ ] **AC-1.2** 流式输出展示「视觉简报 / tag 校验 / 三层 prompt」的逐步思考
- [ ] **AC-1.3** 提交 ComfyUI 后显示「任务已提交，prompt_id = xxx」
- [ ] **AC-1.4** 任务完成时图片以缩略图形式出现在该消息下方
- [ ] **AC-1.5** 点击缩略图打开大图弹窗，可查看完整 `prompt_11` / `prompt_12` / `args.json`
- [ ] **AC-1.6** 失败时显示明确错误（如 ComfyUI 离线、tag 校验无结果），且**不丢失用户输入**

### US-2 迭代微调（场景 B）

> **作为** 创作者，**我希望** 在已有结果上用自然语言微调，**以便** 不必重新写完整 prompt。

**AC：**

- [ ] **AC-2.1** 用户可点击历史图片的「以此为基础修改」按钮，自动引用上一条 prompt 作为上下文
- [ ] **AC-2.2** LLM 接收「上一条 prompt + 用户修改描述」作为输入，生成新 prompt
- [ ] **AC-2.3** 上下文引用最多保留最近 5 轮（按消息计），超出后自动截断防止 token 膨胀
- [ ] **AC-2.4** 修改后的图作为新消息插入会话，原图保留
- [ ] **AC-2.5** 「上下文保留轮数」由用户在设置页配置（US-7.5）

### US-3 参数控制（场景 C）

> **作为** 创作者，**我希望** 用对话告诉工具具体参数，**以便** 不用打开 ComfyUI 也能控制画布、步数等。

**AC：**

- [ ] **AC-3.1** LLM 能识别并设置：`batch_size` / `width` / `height` / `steps` / `cfg` / `seed` / `filename_prefix` / `workflow_id`
- [ ] **AC-3.2** 用户在消息中显式修改后，生成的 args.json 体现该修改
- [ ] **AC-3.3** 涉及画师、构图、画布的决策**仅在用户明确要求时**修改（遵循 v2mini 的「不擅自决定」原则）
- [ ] **AC-3.4** 用户可使用「参数面板」侧边栏直接修改当前会话默认值（非对话式）

### US-4 批量与变体（场景 D）

> **作为** 创作者，**我希望** 一次出多张同一主题的图，**以便** 在同一画面下做姿势/构图变体抽卡。

**AC：**

- [ ] **AC-4.1** 用户说"出 N 张"时，工具生成 1 条 prompt 并设 `batch_size = N`
- [ ] **AC-4.2** N 张图同时显示在结果画廊内，按生成顺序排列
- [ ] **AC-4.3** 单张失败不影响其他张；失败的张标记「生成失败」并展示错误
- [ ] **AC-4.4** MVP 不做"多 prompt 多变体"（每个非融合 job 只用 1 个 prompt，对齐 v2mini 规则）

### US-5 取消与重试（场景 E）

> **作为** 创作者，**我希望** 在生成过程中修改描述并重新提交，**以便** 不必等慢图浪费 GPU 时间。

**AC：**

- [ ] **AC-5.1** 任务运行中显示「取消」按钮
- [ ] **AC-5.2** 点击取消后，工具调用 ComfyUI 队列接口删除该 `prompt_id`
- [ ] **AC-5.3** 取消状态消息显示「已取消」并保留用户输入
- [ ] **AC-5.4** 用户可在取消后立即发送新消息，新任务被提交

### US-6 历史回看与续聊（场景 F）

> **作为** 创作者，**我希望** 找到昨天的某张图并继续在那条会话聊下去，**以便** 不丢失创作脉络。

**AC：**

- [ ] **AC-6.1** 侧边栏展示会话列表，按更新时间倒序
- [ ] **AC-6.2** 每条会话显示标题（自动取首条消息前 20 字，可手动重命名）
- [ ] **AC-6.3** 点击会话加载完整消息历史 + 缩略图
- [ ] **AC-6.4** 续聊时 LLM 自动接收历史消息作为上下文
- [ ] **AC-6.5** 用户可删除单条会话（带二次确认）

### US-7 LLM 配置与参数调节（场景 G）

> **作为** 创作者，**我希望** 在 Web 界面配置 LLM 提供方、上下文行为和推理深度，**以便** 适配不同创作场景（如需要快速反馈 vs 需要深度构思）。

**AC：**

- [ ] **AC-7.1** 设置页提供：LLM API Key / Base URL / Model
- [ ] **AC-7.2** 修改后实时生效（仅配置项修改，无需重启）
- [ ] **AC-7.3** 配置写入 `config.json`（明文）+ 权限提示（API Key 在 UI 中显示为掩码）
- [ ] **AC-7.4** 配置错误（如 API Key 无效）立即在设置页显示，不允许带着坏配置进入对话
- [ ] **AC-7.5** 设置页提供「**上下文保留轮数**」（0–50，默认 5）；0 表示无历史；超出截断；该数值同时影响单图与队列模式
- [ ] **AC-7.6** 设置页提供 **`max_tokens`**（512–8192，默认 4096）与 **`temperature`**（0–2，默认 0.7）
- [ ] **AC-7.7** 设置页提供「**思维深度**」档位：
    - `off`（默认）— 不调用推理
    - `low` / `medium` / `high` — 调用模型推理能力
    - 内部映射：`off` 不传 `reasoning_effort`；`low/medium/high` 分别传 `"low"/"medium"/"high"`（DeepSeek）或 `"thinking"` budget 等级（Claude）
    - 模型不支持时静默忽略，不报错
- [ ] **AC-7.8** 设置页提供「测试调用」按钮：发一条最小请求验证当前配置，10s 内返回成功 / 失败原因

### US-8 ComfyUI Launcher（启动入口）

> **作为** ComfyUI 用户，**我希望** 在 ComfyUI 界面里看到「打开 Chat」按钮，**以便** 一键跳到对话工具。

**AC：**

- [ ] **AC-8.1** 安装自定义节点后，ComfyUI 侧边栏出现「Good Anima Chat」按钮
- [ ] **AC-8.2** 点击按钮在新标签页打开 `http://127.0.0.1:8787`（若服务未启动则提示）
- [ ] **AC-8.3** Chat 服务未启动时按钮变灰，hover 显示「请先启动 chat 服务」

### US-9 双模式工作流调度（场景 I）

> **作为** 创作者，**我希望** 根据需求在 v2mini 5 个 workflow 与自定义 workflow 之间切换，**以便** 既能用 v2mini 的硬约束保证质量，又能在我自己的 workflow 上跑实验。

**AC：**

#### 默认模式（v2mini）

- [ ] **AC-9.1** 对话框顶部有工作流选择器，默认显示 v2mini 5 个 workflow（`anima-txt2img-aesthetic-lora` / `…-base` / `…-artist-mixer` / `…-enhancer` / `…-fixed`）
- [ ] **AC-9.2** 切换工作流后，该会话后续生图使用新 workflow；切换前已提交的任务不受影响
- [ ] **AC-9.3** LLM 在 system prompt 中知道每个 v2mini workflow 的用途与适用场景，能在用户描述匹配时主动推荐
- [ ] **AC-9.4** 用户说"用 X workflow 出图"时，LLM 显式切换 workflow_id
- [ ] **AC-9.5** 默认模式不需要用户感知节点 ID；prompt 由 v2mini 内部注入到约定节点

#### 高级模式（任意 ComfyUI workflow）

- [ ] **AC-9.6** 设置页提供「导入自定义 workflow」按钮，上传 `.json` 文件
- [ ] **AC-9.7** 导入后 UI 列出 workflow 中所有 **CLIPTextEncode 类节点**（按 `node_id` + 节点标题展示）
- [ ] **AC-9.8** 用户指定 **positive prompt 节点**（必填）与 **negative prompt 节点**（可选）
- [ ] **AC-9.9** 工作流与节点映射保存到 DB，后续会话可复用；用户可在「我的工作流」列表中管理（重命名、删除）
- [ ] **AC-9.10** 同一会话可混合使用默认与自定义 workflow（每条消息独立选定）

#### 注入机制

- [ ] **AC-9.11** 工具读取 workflow JSON → 修改指定节点的 `inputs.text` → 提交
- [ ] **AC-9.12** 注入不影响 workflow 中其它节点（如 LoRA、采样器、VSR）
- [ ] **AC-9.13** 工作流修改后**不写回磁盘**，仅在内存中替换再提交（保护用户原始 JSON）
- [ ] **AC-9.14** 若导入的 workflow 不含任何 CLIPTextEncode 节点，UI 拒绝导入并提示

### US-10 场景列表串行生图（场景 H）

> **作为** 创作者，**我希望** 在对话中一次给出多个场景，**以便** 工具自动排队串行生成，每张完成自动注入下一个，我只需坐着看结果。

**AC：**

- [ ] **AC-10.1** 用户说"依次生成 N 个场景：A、B、C…"，LLM 拆解为 N 个独立生图任务（**每任务独立 prompt + args**）
- [ ] **AC-10.2** 工具创建 **JobQueue**，绑定到当前会话，状态显示在对话流右侧队列面板
- [ ] **AC-10.3** 队列**串行执行**：当前 job 完成 → 自动注入下一个 prompt → 提交下一个 job；前一个的失败不会卡住后续（默认行为）
- [ ] **AC-10.4** 每张图生成后立即插入对话流（作为独立 assistant 消息），不等待队列全部完成
- [ ] **AC-10.5** 队列面板展示：当前正在生成的 job、已完成 / 失败 / 等待的任务、进度条
- [ ] **AC-10.6** 队列中每个任务的 `prompt_11` / `prompt_12` / `args` 完整可见，可点开查看
- [ ] **AC-10.7** 用户可**暂停**队列（当前 job 完成后停止；新任务不再提交）
- [ ] **AC-10.8** 用户可**恢复**暂停的队列
- [ ] **AC-10.9** 用户可**取消**队列（立即停当前 job + 清空等待任务）
- [ ] **AC-10.10** 用户可向队列**追加**新任务（追加到末尾）
- [ ] **AC-10.11** 队列全部完成时弹出「全部 N 张已生成」toast
- [ ] **AC-10.12** 队列全部完成时支持「**导出 ZIP**」（一键下载所有图片）
- [ ] **AC-10.13** 队列执行期间用户可在同一会话继续普通对话（非队列消息独立处理，不进入队列）
- [ ] **AC-10.14** 队列绑定当前选定的 workflow（AC-9）；中途切换 workflow 对运行中的队列不生效，对后续追加任务生效
- [ ] **AC-10.15** LLM 在拆解场景列表时遵守 v2mini 硬约束：每个子场景独立走一次「视觉简报 → tag 校验 → 三层 prompt」

## 6. 核心流程

### 6.1 主流程：用户消息 → 生图（单图）

```
[浏览器]
   │ 1. 用户输入消息
   ▼
[前端] ── POST /api/conversations/{id}/messages ──▶ [后端]
   │
   │ 2. 持久化用户消息
   │ 3. 加载最近 N 轮上下文（截断，N 由 US-7.5 配置）
   │ 4. 组装 system prompt（含 v2mini SKILL.md 全文 + LLM 参数 + 当前 workflow）
   │ 5. 调用 LLM（流式，参数含 reasoning_effort）
   │
   │ 6. LLM 流式输出决策 / 视觉简报 / 三层 prompt / args
   │    ◀─── SSE chunks ────
   │
   │ 7. 检测 LLM 是否输出「生图决策」
   │    ├─ 否 → 直接回复，结束
   │    └─ 是 → 提取 workflow_id + args
   │             │
   │             ▼
   │        [Workflow Injector]
   │             │
   │             ├─ 模式 A：v2mini 默认 workflow
   │             │    → 走 args 校验 → comfyui-manager
   │             │
   │             └─ 模式 B：任意 workflow（高级模式）
   │                  → 读取 workflow JSON
   │                  → 修改 prompt 节点 inputs.text
   │                  → 提交
   │             │
   │             ▼
   │        [skill bridge]
   │             │
   │             │ 8. danbooru-tags 校验 hard anchors（仅 v2mini 模式）
   │             │    └─ 校验失败 → 反馈给 LLM 重试（最多 2 次）
   │             │
   │             │ 9. 组装 args.json / 修改后的 workflow JSON
   │             │ 10. 调用 comfyui-manager submit
   │             │
   │             ▼
   │        [ComfyUI 队列]
   │             │
   │             │ 11. 轮询 / 监听 WebSocket
   │             │
   │             ▼
   │        12. 图片落地（监听 ComfyUI output 目录）
   │             │
   │             ▼
   │        13. 持久化 job + image + assistant 消息
   │
   │ 14. 流式推送 [assistant 消息 + 图片结果]
   │    ◀─── SSE chunks ────
```

### 6.2 队列流程：场景列表串行生图

```
[浏览器]
   │ 1. 用户："依次生成：A 雨天天台 / B 魔法森林 / C 夜晚书房"
   ▼
[前端] ── POST /api/conversations/{id}/messages ──▶ [后端]
   │
   │ 2. LLM 流式思考（reasoning_effort = high）
   │ 3. LLM 检测「场景列表」意图 → 调用 tool: enqueue_scene_list
   │    args = [{scene: "A", prompt_11: "...", workflow_id: "..."}, ...]
   │
   │ 4. 工具创建 JobQueue，items 持久化到 DB
   │ 5. 向 SSE 流推送 queue.created 事件
   │
   │ 6. 后台 worker 启动串行执行：
   │    ┌─▶ item[0]：提交 ComfyUI
   │    │       │ 等待完成（事件驱动，非轮询）
   │    │       │ 图片落地 → SSE 推送 image.added
   │    │       │
   │    ├─▶ item[1]：注入下一个 prompt → 提交
   │    │       │ 等待完成
   │    │       │
   │    └─▶ item[N-1]
   │    │
   │    所有 item 完成 → SSE 推送 queue.completed
   │
   ▼
[前端] 在对话流中逐条插入图片，右侧队列面板同步进度
```

### 6.3 异常分支

| 异常                       | 处理                                                                              |
| -------------------------- | --------------------------------------------------------------------------------- |
| LLM API 失败               | 显示「LLM 调用失败，请检查 API Key」按钮，点击跳设置                              |
| LLM 限流                   | 指数退避，最多 3 次；UI 显示「限流中…」                                            |
| 标签校验失败               | 把失败 tag 反馈给 LLM 重试（最多 2 次）；仍失败则向用户说明是哪个 tag 找不到候选  |
| ComfyUI 离线               | 显示「ComfyUI 未启动」，提供「打开 ComfyUI 命令」说明                            |
| ComfyUI 队列满 / 超时      | 显示 `prompt_id` 与队列位置，提示「等待中…」                                      |
| 用户取消                   | 调用 ComfyUI 队列接口删除任务，消息标记「已取消」                                |
| args 缺失关键字段          | 后端校验失败，反馈给 LLM 补全；不允许直接提交                                     |
| 队列中单个 job 失败        | 队列不中断（默认）；用户可点击「整队中止」或「重试该任务」                        |
| 高级模式 workflow 导入失败 | UI 提示原因（JSON 损坏 / 无 CLIPTextEncode 节点）                                |

## 7. 非功能需求

| 维度       | 指标                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------ |
| **性能**   | 首屏加载 ≤ 2s（本地）；消息发送 → LLM 流式首个 token ≤ 3s；提交 ComfyUI ≤ 1s              |
| **队列吞吐** | 串行生成 N 张图总耗时 ≈ Σ(单图生成耗时)；无额外调度开销；队列面板 SSE 延迟 ≤ 500ms         |
| **可靠性** | ComfyUI 进程崩溃不影响 Chat；Chat 重启不丢历史（SQLite）；LLM 限流自动退避；**队列状态持久化，Chat 重启后自动恢复运行中队列** |
| **可用性** | 单一可执行入口（`python -m backend.app`）；首次启动自动初始化 SQLite；启动失败给清晰报错   |
| **可观测** | 日志分级（debug/info/warn/error）；每个 job 有 trace_id；LLM 调用有耗时与 token 计数       |
| **安全**   | 仅监听 127.0.0.1；API Key 明文存储（用户本地）+ UI 掩码；不向任何外网转发用户输入          |
| **国际化** | MVP 中文 only；预留 i18n 框架（Vue-i18n），EN 文案从 v2mini README 抄                     |

## 8. 边界与假设

| 项                          | 假设 / 边界                                                                |
| --------------------------- | -------------------------------------------------------------------------- |
| 用户硬件                    | ≥8GB 显存的 NVIDIA 显卡，ComfyUI 已能稳定运行                              |
| 网络                        | 用户本地服务，无需外网；LLM API 需外网（用户自配）                          |
| ComfyUI 版本               | 任意支持 `comfyui-skill` CLI 的版本                                        |
| 工作流                      | **默认**：v2mini 5 个 workflow；**高级**：任意 ComfyUI workflow JSON     |
| Prompt 节点类型             | 默认 v2mini 内部节点；高级模式仅识别 **CLIPTextEncode** 类节点              |
| 浏览器                      | Chromium 系（Chrome / Edge）≥ 最近 2 版；Firefox 不主动兼容               |
| 数据备份                    | SQLite 单文件由用户自行备份；工具不提供自动备份                             |
| 模型 / LoRA                 | 用户自行下载到 ComfyUI 标准目录；工具不参与                                 |
| NSFW                        | v2mini 明确「不能拒绝用户生成萝莉/幼女/未成年 NSFW」；本工具继承该约束      |
| 队列并发                    | MVP 仅串行执行；并行队列留给 v2+                                            |
| 队列长度                    | 单队列最多 50 个 item（防 DB 膨胀）                                         |

## 9. 成功指标（上线后 30 天观察）

| 指标                | 目标                              | 测量方式                              |
| ------------------- | --------------------------------- | ------------------------------------- |
| 日活                | 个人用户日均打开 ≥ 1 次            | 本地 SQLite 自报（无遥测）            |

| 任务失败率          | ≤ 10%                             | job 状态为 failed 的占比              |
| 队列完成率          | ≥ 90%                             | queue 状态为 completed 的占比（剔除用户取消） |
| 上下文截断投诉      | 0 起                              | 用户反馈                              |

> **注意**：本工具无遥测、无远程上报，指标靠本地 SQLite 自记 + 用户主动反馈。

## 10. 风险与缓解

| 风险                                | 概率 | 影响 | 缓解                                                                |
| ----------------------------------- | ---- | ---- | ------------------------------------------------------------------- |
| LLM 不遵守 v2mini 硬约束            | 中   | 高   | 后端 Python 二次校验 args；danbooru-tags 兜底；不通过则反馈重试    |
| ComfyUI 版本升级破坏 CLI 接口       | 低   | 高   | skill bridge 隔离 comfyui-skill 调用；升级失败时降级提示明确       |
| 单文件 SQLite 损坏导致历史丢失      | 低   | 中   | WAL 模式 + 启动时完整性检查；损坏提示用户从备份恢复                 |
| 流式响应在弱网下卡顿                | 中   | 低   | 客户端断线重连重放最后一条 SSE                                       |
| 用户期望"画师融合"等 v1 不做功能    | 高   | 低   | PRD §4.2 场景表 + 设置页「即将推出」列表管理预期                     |
| 队列长时间运行导致 Chat 重启时丢状态 | 低   | 高   | 队列状态 + items 全部持久化到 SQLite；启动时扫描 running 队列并恢复  |
| 高级模式导入恶意 workflow           | 低   | 中   | 仅在 127.0.0.1 提交；不修改 ComfyUI 工作流磁盘文件；JSON 大小限制 5MB |
| LLM 把"依次生成"误解为"一次生成多张"| 中   | 中   | system prompt 明确「场景列表 = 独立 job 序列」；后端解析时区分 intent |
